# ✅ Исправление: Изменение пароля для существующего пользователя

## Проблема

Когда пользователь:
1. Регистрируется и подтверждает email → аккаунт создается
2. Нажимает "Изменить email или пароль"
3. Меняет пароль и регистрируется снова
4. Подтверждает код

**Ошибка:** `Unique constraint failed` - пользователь уже существует

## Решение

Изменена логика в `/api/auth/verify-email/verify`:

### Было (create):
```typescript
const user = await prisma.users.create({
  data: {
    id: userId,
    email: pendingReg.email,
    password_hash: pendingReg.password_hash,
    is_email_verified: true,
    onboarding_completed: false,
  },
});
```

**Проблема:** Если пользователь уже существует → ошибка

### Стало (upsert):
```typescript
const user = await prisma.users.upsert({
  where: { email: pendingReg.email },
  create: {
    id: userId,
    email: pendingReg.email,
    password_hash: pendingReg.password_hash,
    is_email_verified: true,
    onboarding_completed: false,
  },
  update: {
    password_hash: pendingReg.password_hash, // Обновляем пароль
    is_email_verified: true,
  },
});
```

**Решение:** 
- Если пользователь НЕ существует → создается новый
- Если пользователь существует → обновляется пароль

### 1. Удаление старых сессий
```typescript
// Удаляем старые сессии пользователя (если есть)

  where: { user_id: user.id },
});
```

**Зачем:** При изменении пароля старые сессии должны быть недействительны

### 2. Upsert подписки
```typescript
await prisma.subscriptions.upsert({
  where: { user_id: user.id },
  create: { /* создание */ },
  update: { /* обновление */ },
});
```

**Зачем:** Если подписка уже существует, обновляем её вместо создания новой
